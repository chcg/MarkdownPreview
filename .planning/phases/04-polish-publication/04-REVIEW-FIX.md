# Phase 04: Code Review Fix Report

**Fix Date:** 2026-04-10
**Scope:** Critical + Warning
**Iteration:** 1

## Fixed

### CR-01: Unvalidated zoom level applied directly to `document.body.style.zoom`

**File:** `MarkdownPreview/assets/preview.html:749`
**Commit:** `8951d1b`
**Change:** Replaced the direct `document.body.style.zoom = String(msg.level)` assignment with a bounds-clamped path: `parseFloat(msg.level)` is checked with `isFinite`, floored to `1.0` if less than `0.1` (rejects 0, negative, NaN), and capped at `8.0` (800%) before being applied. Prevents a corrupted `settings.json` value from collapsing the viewport or freezing the renderer.

### WR-01: `WideCharToMultiByte` return value used as buffer size without checking for 0

**File:** `MarkdownPreview/src/PreviewPanel.cpp:482-495`
**Commit:** `463e8cf`
**Change:** Added `if (utf8len <= 0) return;` immediately after the first `WideCharToMultiByte` call (markdown content conversion), and `if (pathLen <= 0) return;` after the second call (file path conversion). Both guards bail out of `renderMarkdown()` before constructing the `std::string` buffers, preventing silent empty-render data loss when the conversion fails.

### WR-02: `SCI_GETTEXT` buffer one byte too small when `SCI_GETLENGTH` returns 0

**File:** `MarkdownPreview/src/PreviewPanel.cpp:445-446`
**Commit:** `ee67453`
**Change:** Changed the early-return guard from `if (len < 0)` to `if (len <= 0)`, so an empty document (len == 0) is caught immediately at the top of `getCurrentText()` and returns `L""` without allocating a 1-byte buffer or proceeding through the conversion path. Clarifies intent and removes the fragile dependency on the downstream `utf8Text.empty()` check.

### WR-03: `NavigationCompleted` event fires on every navigation, not just the first

**File:** `MarkdownPreview/src/PreviewPanel.cpp:341-366`
**Commit:** `b72157c`
**Change:** Added a self-unregistration block at the top of the `NavigationCompleted` lambda: checks `m_navigationCompletedToken.value != 0`, calls `m_webview->remove_NavigationCompleted(m_navigationCompletedToken)`, then zeroes the token. This ensures the setup sequence (zoom replay, theme replay, pending render) fires exactly once on the initial navigation and cannot be re-triggered by any future `Navigate()` calls.

## Skipped

### WR-04: `manifest.json` ships with unresolved placeholder `id` field

**File:** `manifest.json:4`
**Reason:** The `"id"` field must contain the SHA-256 hash of the release ZIP, which is generated by `scripts/package.ps1` at packaging time. This cannot be computed without first building and packaging the release artifacts. Automated fix is not possible.
**Manual action required:**
1. Build the release ZIP by running `scripts/package.ps1`.
2. Copy the SHA-256 hash printed by the script.
3. Update `manifest.json` line 4: replace `"REPLACE_WITH_SHA256_FROM_PACKAGE_PS1"` with the actual hash.
4. Consider extending `package.ps1` to write the hash back into `manifest.json` automatically to prevent recurrence.
