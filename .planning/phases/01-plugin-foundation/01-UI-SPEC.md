# Phase 1 — UI Design Contract

> Visual and interaction contract for the plugin foundation. This phase has two UI surfaces: (1) a welcome page rendered in WebView2 (HTML/CSS), and (2) a Win32 fallback message when WebView2 is missing. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

---

## Design System

| Property | Value |
|----------|-------|
| Tool | none (native C++ plugin, not a web frontend) |
| Preset | not applicable |
| Component library | Win32 controls + WebView2 HTML |
| Icon library | none (Phase 1 has no icons) |
| Font | System default (Segoe UI on Windows 10/11) |

**Note:** This is a Notepad++ C++ plugin. There is no React, no shadcn, no browser-based component library. The UI contract covers two surfaces: an HTML welcome page inside WebView2, and a Win32 SysLink fallback control.

## Color

Phase 1 uses minimal color. The welcome page must look correct in both light and dark Notepad++ contexts. Phase 2 adds full theme switching (THME-01, THME-03). For Phase 1, use a neutral scheme that works standalone.

### Welcome Page (light default)

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | #FFFFFF | Page background |
| Secondary (30%) | #F6F8FA | Not used in Phase 1 (no cards/sections) |
| Accent (10%) | #0969DA | Hyperlinks only (if any appear on welcome page) |
| Text primary | #1F2328 | Heading and body text |
| Text secondary | #656D76 | Version label, hint text |
| Destructive | not applicable | No destructive actions in Phase 1 |

Accent reserved for: hyperlinks on the welcome page (none expected in Phase 1, but declared for consistency with Phase 2 github-markdown-css adoption).

### Win32 Fallback

| Role | Value | Usage |
|------|-------|-------|
| Background | Inherited from Notepad++ docking panel | Panel background |
| Text | System default (COLOR_WINDOWTEXT) | Message body |
| Link | System default (SysLink blue) | "Download WebView2 Runtime" clickable URL |

Win32 fallback inherits all colors from the system theme. Do not override.

## Welcome Page Layout Specification

The welcome page (`assets/welcome.html`) is a single centered content block.

```
+------------------------------------------+
|                                          |
|              (48px top pad)              |
|                                          |
|          MarkdownPreview                 |  28px, semibold, #1F2328
|          v0.1.0                          |  14px, regular, #656D76, 8px below heading
|                                          |
|              (24px gap)                  |
|                                          |
|    Open a .md file to see the preview    |  16px, regular, #656D76
|                                          |
+------------------------------------------+
```

- Content block: centered horizontally and vertically in the WebView2 viewport.
- Text alignment: center.
- No images, no icons, no borders, no shadows.
- Page background: #FFFFFF.
- The welcome page must be a standalone HTML file with inline CSS (no external dependencies). This ensures it loads instantly from the virtual host mapping.

## WebView2 Missing Fallback Layout Specification

When `GetAvailableCoreWebView2BrowserVersionString` returns failure, the docking panel shows a Win32 SysLink control instead of WebView2.

```
+------------------------------------------+
|  (20px, 20px)                            |
|  WebView2 Runtime is required for        |
|  Markdown Preview.                       |
|                                          |
|  [Download WebView2 Runtime]             |  <- SysLink clickable, opens browser
|                                          |
+------------------------------------------+
```

- SysLink control positioned at (20, 20) within the panel client area.
- Control size: 400x100 pixels (sufficient for wrapped text at default DPI).
- Link opens `https://developer.microsoft.com/microsoft-edge/webview2` via `ShellExecuteW`.
- Handle NM_CLICK and NM_RETURN notifications in WM_NOTIFY.
- Background: inherited from docking panel (no custom painting).

## Interaction Contract

### Toggle Behavior (INFR-01)

| State | Action | Result |
|-------|--------|--------|
| Panel hidden | User presses Ctrl+Shift+M or clicks menu item | Panel appears docked right (D-01), 50% width (D-03) |
| Panel visible | User presses Ctrl+Shift+M or clicks menu item | Panel hides |
| Panel hidden | Notepad++ restarts | Panel state restored from settings (D-04) |
| First ever toggle | User presses Ctrl+Shift+M | Panel registered with NPPM_DMMREGASDCKDLG, then shown. WebView2 detection occurs here (D-06). |

### Menu Checkmark

The "Toggle Preview" menu item shows a checkmark when the panel is visible. Update via `::SendMessage(nppData._nppHandle, NPPM_SETMENUITEMCHECK, funcItems[0]._cmdID, panelVisible)`.

### Panel Resize

When the docking panel is resized (user drags splitter), the WebView2 controller bounds must update to fill the panel. Handle `WM_SIZE` in the panel's WndProc and call `controller->put_Bounds(newBounds)`.

## Phase-Specific Notes

1. **No theme switching in Phase 1.** The welcome page uses a fixed light color scheme. Theme auto-detection (THME-03) and dark/light themes (THME-01) are Phase 2 scope. The colors declared here will be superseded by github-markdown-css in Phase 2.

2. **Welcome page is temporary.** In Phase 2 (REND-01), the welcome page is replaced by the live markdown preview when a .md file is open. The welcome page remains as the "no file open" state.

3. **Win32 fallback is permanent.** The WebView2-missing fallback UI persists across all phases unchanged.

4. **No custom fonts, no icon assets, no images.** Phase 1 ships zero visual assets beyond `welcome.html`. System font (Segoe UI) is used everywhere.

5. **WebView2 settings for Phase 1.** Disable: default context menus, DevTools, status bar. These may be selectively re-enabled in later phases.
