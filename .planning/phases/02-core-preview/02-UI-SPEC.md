# Phase 2 — UI Design Contract

> Visual and interaction contract for Phase 2: Core Preview.
> Generated by gsd-ui-researcher. Verified by gsd-ui-checker.
>
> Scope: The UI being specified is the WebView2-hosted HTML/CSS/JS layer —
> `preview.html` and the `welcome.html` idle page. There is no React/Next.js
> component tree. No shadcn gate applies.

---

## Design System

| Property | Value |
|----------|-------|
| Tool | none (hand-authored HTML/CSS in assets/) |
| Preset | not applicable |
| Component library | none — plain HTML elements styled with inline `<style>` blocks |
| Icon library | none — text labels only in Phase 2 |
| Font | "Segoe UI", system-ui, sans-serif (source: welcome.html — carry forward) |

> Rationale: The plugin is a native C++ Win32 application. WebView2 renders
> local HTML files served via virtual host. There is no npm build pipeline,
> no React, and no component registry. Design tokens are CSS custom properties
> declared in `preview.html`'s `<style>` block.

---

## Spacing Scale

Declared values (multiples of 4 only). Applied as CSS custom properties in
the `<style>` block of `preview.html` and `welcome.html`.

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Inline code padding, icon-adjacent gaps |
| sm | 8px | List item gaps, tight element spacing |
| md | 16px | Default paragraph spacing, content padding |
| lg | 24px | Section breaks between content blocks |
| xl | 32px | Outer content padding (`.markdown-body` wrapper) |
| 2xl | 48px | Idle/empty page vertical centering inset (source: welcome.html `.content` padding-top) |
| 3xl | 64px | Not used in Phase 2 |

Exceptions:
- `.markdown-body` horizontal padding: 32px on each side (xl token), matching
  github-markdown-css defaults.
- Scroll sync does not add any padding — it scrolls to the element's existing
  position; no extra offset needed in Phase 2.

## Typography

Phase 2 hosts two distinct typographic contexts: (1) the **preview content**
(governed by `github-markdown-css` — do not override its type scale); and
(2) the **plugin chrome** — idle page, error state, and WebView2 runtime
missing message (governed by the declarations below).

### Plugin Chrome Typography (welcome.html, error state, no-runtime message)

Source: `welcome.html` — carry forward and extend.

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Display (plugin name heading) | 28px | 600 (semibold) | 1.2 |
| Body / hint text | 16px | 400 (regular) | 1.5 |
| Label / version badge | 14px | 400 (regular) | 1.5 |
| Error detail (stack/path info) | 13px | 400 (regular) | 1.4 |

Maximum 4 sizes declared. Maximum 2 weights declared (400 + 600).

### Preview Content Typography

Governed entirely by `github-markdown-css` (github-markdown-light.css /
github-markdown-dark.css). Do NOT declare custom type rules that conflict
with it. The `.markdown-body` class manages all heading, paragraph, code,
and table sizes.

highlight.js themes (hljs-github.min.css / hljs-github-dark.min.css) govern
code block monospace type. Do not override.

## Color

### Preview Content Color

Governed by `github-markdown-css` light/dark variants and the matching
highlight.js theme. Switch by toggling `<body>` class between
`markdown-body-light` and `markdown-body-dark`. Do not declare custom
overrides to github-markdown-css color tokens.

### Plugin Chrome Color (idle page, error states)

The 60/30/10 split below applies to the plugin chrome surfaces only.

| Role | Light Value | Dark Value | Usage |
|------|------------|------------|-------|
| Dominant (60%) | #FFFFFF | #0D1117 | Page/panel background (source: welcome.html + GitHub dark background) |
| Secondary (30%) | #F6F8FA | #161B22 | Inline code background, blockquote background (mirrors github-markdown-css) |
| Accent (10%) | #0969DA | #58A6FF | Reserved for: hyperlinks in rendered content only |
| Destructive | #CF222E | #F85149 | Reserved for: error state heading text, WebView2 missing error text |

Accent reserved for: **hyperlinks in rendered content only** — no other
element uses accent color in Phase 2. Buttons, export triggers, and
navigation are menu-driven (Win32 menus, not HTML). There are no
HTML-level buttons in the preview page in Phase 2.

Destructive reserved for: error state heading and WebView2 runtime-missing
message heading. No interactive destructive actions exist in Phase 2's
HTML layer (export is a menu item, overwrite is silent per D-10).

> Note on D-10: The export overwrites without a prompt (CONTEXT.md D-10).
> There is no destructive confirmation dialog in the HTML layer for Phase 2.
> The Win32 menu item label handles intent communication.

## Copywriting Contract

### Idle State (no .md file open — welcome.html)

| Element | Copy |
|---------|------|
| Heading | MarkdownPreview |
| Version label | v0.1.0 (source: welcome.html — carry forward) |
| Hint body | Open a .md file to see the preview |

### Empty File State (file active but document is empty)

| Element | Copy |
|---------|------|
| Empty state heading | (none — render blank; do not show placeholder text inside the markdown body area) |
| Empty state body | (none — blank preview is correct when the document is empty) |

Rationale: A blank preview when the file is empty is the expected behavior.
Injecting placeholder copy inside the rendered area would confuse the user
into thinking the preview text is part of their document.

## Interaction Contract

### Auto-open Behavior (D-01)

- Trigger: NPPN_BUFFERACTIVATED + file path ends with `.md`
- Panel opens automatically. No user confirmation.
- If panel was previously hidden: show it.
- If non-.md file is activated: hide preview panel, show idle page (welcome.html).

### Live Rendering (D-02, D-03)

- Trigger: SCN_MODIFIED → 300ms debounce → full re-render
- YAML frontmatter (between leading `---` delimiters) is stripped before render
- No loading indicator in Phase 2 (render is fast enough; debounce masks latency)
- Large files (>500KB): debounce timer remains 300ms; no special handling in Phase 2

### Scroll Sync (D-04)

- Trigger: SCN_UPDATEUI (caret position change)
- C++ sends `{type:"scroll", line: N}` (0-indexed, matching Scintilla)
- JS finds element with `[data-line]` attribute closest to N and calls
  `element.scrollIntoView({behavior: "smooth", block: "start"})`
- If no element found for line N: no scroll, no error

### Theme Switching (D-05, D-06)

- Trigger: NPPN_DARKMODECHANGED or initial NPPM_ISDARKMODEENABLED check
- C++ sends `{type:"theme", dark: true/false}`
- JS swaps two CSS `<link>` tags: github-markdown theme + highlight.js theme pair
- Transition is instant (no CSS transition animation on theme swap)
- Light: `github-markdown-light.css` + `hljs-github.min.css`
- Dark: `github-markdown-dark.css` + `hljs-github-dark.min.css`

### Custom CSS (D-07)

- Loaded as `<link id="custom-css" rel="stylesheet">` tag appended after base theme
- If custom.css is absent: `<link>` tag is omitted entirely (not present with empty href)
- C++ reads custom.css content at render time and sends via message; JS injects inline `<style>` tag
- Custom CSS overrides win (cascade order: github-markdown → hljs → custom)

### Image Resolution (D-08)

- All relative image `src` values are rewritten before markdown-it parses: `./img.png` → `https://file.mdpreview/img.png`
- Virtual host `file.mdpreview` maps to current file's parent directory
- Absolute URLs (http/https) are left unchanged
- On file switch: clear old virtual host mapping, set new one before sending render message

### HTML Export (D-09, D-10)

- Trigger: Win32 menu item "Export as HTML"
- C++ sends `{type:"export"}` message to JS
- JS: fetches all `<img src>` URLs, converts to base64 data URIs, inlines all CSS, serializes DOM
- JS sends `{type:"exportReady", html: "..."}` back to C++
- C++ writes to `{sourceFilePath}.html` (replaces `.md` extension), silent overwrite
- No success notification in Phase 2 HTML layer
