**Change 1 — Add Utf8ToWide() static helper.**

// UTF-8 to wide string conversion helper.
// Uses MultiByteToWideChar(CP_UTF8) — the only correct approach for editor content.
// Never use std::wstring(str.begin(), str.end()) — that zero-extends bytes, corrupting
// any multi-byte UTF-8 sequence (accented chars, CJK, emoji).
static std::wstring Utf8ToWide(const std::string& utf8) {
    if (utf8.empty()) return L"";
    int wlen = ::MultiByteToWideChar(CP_UTF8, 0,
        utf8.c_str(), static_cast<int>(utf8.size()), nullptr, 0);
    if (wlen <= 0) return L"";
    std::wstring w(static_cast<size_t>(wlen), L'\0');
    ::MultiByteToWideChar(CP_UTF8, 0,
        utf8.c_str(), static_cast<int>(utf8.size()), &w[0], wlen);
    return w;
}
```

    function stripFrontmatter(markdown) {
        // Strip UTF-8 BOM (U+FEFF) if present — Scintilla returns raw bytes including BOM.
        // Without this, files with BOM skip frontmatter detection entirely.
        if (markdown.charCodeAt(0) === 0xFEFF) {
            markdown = markdown.slice(1);
        }
        if (markdown.startsWith('---')) {
            // Match both \n--- and \r\n--- as the closing delimiter (WR-05).
            var end = markdown.search(/\r?\n---(\r?\n|$)/);
            if (end !== -1) {
                // Advance past the matched \n--- (plus optional trailing \r\n)
                var afterDelim = markdown.indexOf('\n', end + 1) + 1;
                return markdown.slice(afterDelim).trimStart();
            }
        }
        return markdown;
    }
```

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Filesystem → C++ (custom.css read) | C++ reads a file from a hardcoded path derived from APPDATA. The path is not user-supplied at runtime — it is constructed entirely in C++. |
| C++ → WebView2 JS (PostWebMessageAsJson) | JSON payload containing markdown text (arbitrary user content) and CSS file content crosses into the renderer process. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-02-05-01 | Tampering | GetEnvironmentVariableW(APPDATA) | mitigate | Check return value (ret > 0 && ret < MAX_PATH) before using. Falls back to nullptr JSON field. Implemented in Change 3. |
| T-02-05-02 | Information Disclosure | custom.css content via j["customCss"] | accept | CSS is the user's own file applied to their own preview. Content reaches the renderer via PostWebMessageAsJson (JSON-encoded). CSS textContent assignment in JS (not innerHTML) prevents script injection. WebView2 DENY_CORS on both virtual hosts blocks CSS url() exfiltration. Low risk. |
| T-02-05-03 | Elevation of Privilege | Path traversal via APPDATA expansion | accept | The path suffix `\Notepad++\plugins\config\MarkdownPreview\custom.css` is a hardcoded string literal — no user-controlled path component. APPDATA is a system environment variable set by Windows; its value cannot be injected by document content. Risk is low. |
| T-02-05-04 | Denial of Service | Large custom.css file exhausting memory | mitigate | ifstream reads entire file into std::string. Consider: CSS files are typically under 100 KB. A reasonable guard (e.g., skip if file size > 1 MB) can be added. For Phase 2, the risk is user-self-DoS only — no remote attacker can write to %APPDATA%. Accept as-is for Phase 2, document as a future hardening item. |
| T-02-05-05 | Tampering | Utf8ToWide() with malformed UTF-8 input | accept | MultiByteToWideChar with CP_UTF8 and no MB_ERR_INVALID_CHARS flag silently replaces invalid sequences with U+FFFD. The rendered output may show replacement characters but will not crash or execute code. This matches the behavior of the existing getCurrentText() pattern. |
</threat_model>
